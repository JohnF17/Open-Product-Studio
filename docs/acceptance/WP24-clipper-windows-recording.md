# Clipper recording in the Windows desktop app

## Disposition

Installed Windows capture is gated. Clipper Source keeps the browser chooser where supported and local video import in the packaged app. The desktop recording control, Electron permission handling, T3 preview recording, and preview profiles were left as found. This investigation did not launch an app window, enumerate OS windows, acquire screen pixels, change firewall settings or use CI.

## Packaged entry and source findings

- A read-only check of the retained Windows x64 NSIS stage `t3code-desktop-win-stage-zDwbzj` confirmed `Open Product Studio (Beta).exe` at version `0.1.10.0`. Its `resources/app.asar` names `apps/desktop/dist-electron/boot.cjs` as `main`. That file requires the bundled `main.cjs`. The packager log records Electron `44.10.1`. This retained artifact establishes the entry and is separate from qualifying a new candidate.
- At source base `0eb9551dc0d1`, `DesktopApp` installs the packaged asset handler and `DesktopWindow` loads `open-product-studio://app/` in its sandboxed main window. `useClipperRecording` excludes renderers with `desktopBridge`, so this entry offers file import and omits the browser recording button. [Packager](../../scripts/build-desktop-artifact.ts) · [Boot](../../apps/desktop/src/boot.ts) · [Desktop app](../../apps/desktop/src/app/DesktopApp.ts) · [Main window](../../apps/desktop/src/window/DesktopWindow.ts) · [Desktop protocol](../../apps/desktop/src/electron/ElectronProtocol.ts) · [Clipper hook](../../apps/web/src/features/studio/useClipperRecording.ts)
- Electron is pinned to `44.10.1`. Its system picker option is macOS 15+ only and bypasses the JavaScript handler when available. The native availability check returns `false` on Windows. Windows does provide `GraphicsCapturePicker`, but the pinned Electron API does not expose it as a video source picker. Microsoft's desktop integration requires binding the picker to its owner's native window handle. [Electron pin](../../apps/desktop/package.json) · [Electron Session API](https://github.com/electron/electron/blob/v44.10.1/docs/api/session.md#sessetdisplaymediarequesthandlerhandler-opts) · [Electron picker availability](https://github.com/electron/electron/blob/v44.10.1/shell/browser/api/electron_api_desktop_capturer.cc#L568-L574) · [Windows GraphicsCapturePicker](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.graphicscapturepicker)
- `PreviewManager.startRecording` installs the display-media handler on `wc.hostWebContents.session`, arms the host's main frame tree node, and triggers `getDisplayMedia` in that host via `executeJavaScript(..., true)`. `clearPendingRecording` and the arm timeout preserve one-shot behavior. The handler returns the armed preview guest's `mainFrame` as the video source only when the requesting frame matches. The requester is the trusted app frame where Clipper also runs. The renderer's `captureTabMediaStream` uses frame-rate constraints and `audio: false`. In a sparse checkout, inspect it with `git show 0eb9551dc0d1:apps/web/src/browser/browserRecording.ts`. [Preview manager](../../apps/desktop/src/preview/Manager.ts#L3363)
- Electron stores one `display_media_request_handler_` per browser context. Installing a second handler replaces the first. The request offers `frame`, `securityOrigin`, `videoRequested`, `audioRequested`, and `userGesture`. The preview call supplies synthetic activation and Electron does not pass the frame-rate constraints or a caller-provided transaction ID to the handler. A bare Clipper request can therefore consume a pending preview arm from the same frame. Conversely, treating every unarmed main-frame request as a Clipper request would let a delayed preview request open the native picker. A main-frame, origin and gesture check alone cannot dispatch these two flows safely. [Electron browser context](https://github.com/electron/electron/blob/v44.10.1/shell/browser/electron_browser_context.cc#L855-L864) · [Electron request fields](https://github.com/electron/electron/blob/v44.10.1/docs/api/session.md#L1022-L1058)

## Smallest next gate

Prove request isolation with a mocked, single owner of the packaged app session's display-media handler before adding a visible desktop control. The gate spans both request producers and their completion paths. A timeout or cancellation can revoke authorization immediately, but must not make an unresolved old request eligible for the other route. Test late delivery and callback settlement explicitly. Keep the current preview arm, target, and revocation behavior in the preview branch. Leave each guest partition and other windows outside the Clipper authorization path.

The controller for that gate must meet these contracts.

| Operation | Contract |
| --- | --- |
| Start | Packaged Windows only. Bind to the current `open-product-studio://app/` main document and live main window. Require a current renderer user activation on the Clipper action and verify `request.userGesture` on its video-only request. Deny requests from subframes, guest sessions, other windows, agent paths and stale documents. |
| Route | Reserve a single pending transaction, correlated to its initiating flow. A preview arm must never satisfy a Clipper request, and Clipper authorization must never satisfy a late preview request. Recheck authorization immediately before completing the Electron callback, consume it once, and deny unmatched requests. |
| Choose | Keep window titles and source IDs in main. After authorization, request only `window` sources from `desktopCapturer.getSources`, with a zero-size thumbnail and `fetchWindowIcons: false`. Use an abortable native dialog owned by the visible main window. Cancel is the default and Escape action. Grant video for exactly the explicitly selected, still available named source. Empty results, ambiguous or stale selections, errors, dismissal and cancellation deny capture. |
| Revoke | Cancel a pending pick on project exit, navigation, hide/minimize, close, reload, renderer loss and window replacement. Deny late enumeration or dialog completions. After a grant, the recorder must release its actual tracks on hide/close and stop on source loss. Stop late-arriving tracks before building a recorder. Resolve a picker denial once. |
| Output | Keep existing local `MediaRecorder` ingestion and its time/size limits. Request no audio, grant no audio, and strip any unexpected audio tracks before recording. Preserve the existing clip source after denial, empty output or cancellation. |

Electron already supplies metadata-only enumeration options and an owner-modal, cancelable `showMessageBox` on Windows. These are sufficient to prototype the named-window choice after the broker gate. Treat a Windows window-only picker as window recording in the UI. [Electron DesktopCapturer API](https://github.com/electron/electron/blob/v44.10.1/docs/api/desktop-capturer.md#desktopcapturergetsourcesoptions) · [Electron dialog API](https://github.com/electron/electron/blob/v44.10.1/docs/api/dialog.md#dialogshowmessageboxwindow-options)

## Evidence and pending installed validation

On Windows build `26100`, Node `26.13.1`, Vite+ Vitest `5.0.5`, the existing Node-only mocks passed from the `runtime-suites` fixture. The four preview implementation and test files matched the source base by Git blob hash.

| Fixture directory | Command | Result |
| --- | --- | --- |
| `apps/desktop` | `..\..\node_modules\.bin\vp.cmd test run --config vite.config.ts --project unit src/preview/Manager.test.ts` | 88 passed, exit 0 |
| `apps/web` | `..\..\node_modules\.bin\vp.cmd test run --config vite.config.ts --project unit src/browser/browserRecording.test.ts` | 4 passed, exit 0 |

The manager suite uses fake Electron sessions, frame IDs and windows. The renderer suite uses fake media streams. These results establish existing preview behavior. Before enabling Clipper capture, add mocks for same-frame cross-route races, forged or unrelated senders, missing gesture, audio requests, cancel/default/empty choice, stale source, one-shot replay, navigation/window replacement and immediate disposal of tracks delivered after hide or close. [Preview manager tests](../../apps/desktop/src/preview/Manager.test.ts) · [Clipper browser fixture tests](../../apps/web/src/features/studio/ClipperSource.browser.test.tsx)

The `clipper-source-qa/apps/web` fixture also passed two filtered headless tests using `..\..\node_modules\.bin\vp.cmd test run --config fixture.config.mts --project browser src/features/studio/ClipperSource.browser.test.tsx -t 'stops all tracks|offers file import'` (exit 0, five tests filtered out). The chooser is mocked in the late-track test. The second test stubs `desktopBridge` and checks that file import remains available with no chooser button. The fixture uses the matching recording hook and tests with an earlier file and link import implementation. This run supplies browser fixture evidence only.

Installed validation is pending on an exact candidate from `pnpm run dist:desktop:win:x64`. Record the source revision, installer SHA-256, Windows build, and packaged Electron and Chromium versions. On a disposable Windows profile or VM, install the candidate and open Studio from its Start menu shortcut. Open Clipper Source. With two synthetic, visibly distinguishable window fixtures and an audible fixture cue, use the real chooser and select one named window. Verify that only the selected fixture appears in the saved recording and that the file has a video track and zero audio tracks. Reopen the result in Clipper and verify local playback. Record a fresh attempt for each negative case: Escape/default Cancel, empty source list, disappearing selected window, app hide/minimize/close or project exit during both selection and recording, and reload or navigation while selection is pending. Verify no late capture or empty replacement, and no frames continue after revocation. Then record a normal T3 preview before and after the Clipper run and check denial from an unarmed preview page, app subframe, other window and provider path. This requires a separately authorized live run on the disposable profile.
