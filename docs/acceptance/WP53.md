## Launch chain on this host

1. `apps/server/src/provider/Drivers/CodexDriver.ts` (around lines 186–277) merges host and instance environments, resolves the Codex home layout, materializes a shadow home where applicable and constructs the adapter. The normal status path can refresh the model catalog and request account, configuration, model, usage and skill information. We did not use it. No real instance ID, home binding, credential subject or endpoint was established.
2. `apps/server/src/orchestration-v2/Adapters/CodexAdapterV2.ts` (1578–1608, 1765–1815) chooses the configured binary or `codex`, passes environment and optional `CODEX_HOME`, and opens a child-process stdio client. `apps/server/src/provider/codexLaunchArgs.ts` builds `app-server -c thread_unload_delay_secs=0` followed by tokenized launch arguments. A nonblank `T3CODE_CODEX_LAUNCH_ARGS` takes precedence over configured arguments. The resulting argument list, effective home/config layers and transport matter to qualification.
3. `apps/server/src/process/agentScope.ts:104` selects the default scope on Windows. In `packages/shared/src/AgentScope.ts` its wrapper returns the command and arguments, stop is a no-op and kill returns false. The adapter's two-second force-kill setting concerns process lifetime. Neither establishes a Windows policy for descendants.
4. `packages/shared/src/shell.ts:1021` returns an executable and argv with shell disabled for a resolved native executable. For a resolved CMD shim on this adapter path it builds an escaped command line and enables the shell. The installed Windows npm chain is **CMD shell → codex.cmd → node.exe → bin/codex.js → vendor native codex.exe**. The shim chooses adjacent Node if present, otherwise PATH Node. The JS launcher resolves the platform package, forwards arguments, copies its environment with package-manager markers, and spawns a child with inherited stdio on Windows. PowerShell also discovers a codex.ps1 shim. The probes used the absolute native EXE and skipped both shims. This reconstructs the available route from files and source. A daemon with different PATH, managed installation, configured binary or home could choose a different chain.
5. The native layout names the target `x86_64-pc-windows-msvc`, entrypoint `bin/codex.exe`, resource and PATH directories. The PE machine field was 0x8664 on Windows NT 10.0.26100.0. Code-mode host, command runner, Windows sandbox setup and ripgrep are shipped beside the entrypoint. Their presence establishes neither activation nor restriction of a shell, MCP process or nested child.
