## Reader files and private backups

Digital product Export asks for a public title and shows the manuscript in a sandboxed preview. Approval enables editable UTF-8 text and a standalone, print-friendly HTML file. Open the HTML in a browser and use Print to save a PDF. The private project title, brief, audience and outline stay out of the reader files. Reopen preserves review of the saved version. Editing a manuscript field requires another review. [Reader files and restore walkthrough](WP08/manuscript/README.md).

Download private backup in the project header includes authored work for the current project. Projects > Import backup restores it under a new identifier in the current workspace. Each restored project has its own numbered copy label in Projects and the editor. Local import drops approval state and grants. Studio restores supported older files. Recognized credential and approval fields are discarded. Other unrecognized authored text stays in an inert private archive and survives another backup. The header and the Digital product and Replica private-download controls use the same backup format. Treat the complete file as private, including sensitive text an author may have typed. An ambiguous early Replica brief offers a partial copy after identifying the missing material. Files above 8 MiB require confirmation before reading. The interactive restore limit is 32 MiB, with no cue or candidate row cap. Larger projects can still download a complete private JSON archive. The backup belongs to one project. Engine settings, provider accounts, billing, other workspaces and a complete installation are outside its scope.
