# Assistance in the seven project builders

Select **Suggest** below the sheet heading to get help with the current decision. **Explain** describes what that step is for. **Tools and models** shows the built-in tool, available drafting routes and optional integrations for the step. The same controls follow the creator through the sliding sheets and respect the selected appearance and reduced-motion setting.

| Builder | Example assistance |
| --- | --- |
| Blank | Turn a rough idea into an editable note and a next action. |
| Digital product | Shape sections around the chosen format, reader and brief. |
| Video | Draft narration and shot directions for the chosen visual treatment. Time authored captions in Storyboard and download reviewed WebVTT in Export. |
| Clipper | Propose framing and caption directions. The separate footage workflow handles actual source marks and timed evidence. |
| Replica | Draft an original interface sketch and an observable acceptance scenario. |
| Day Trader | Structure a private practice journal and explain the current exercise locally. |
| Affiliate Storefront | Draft public storefront copy in Design. Source verification, referral links and merchant actions remain with their own controls. |

## Routes and user flow

1. The initial route favors an available on-device model, followed by an eligible T3 connection where the category permits it. A creator can always use the local starter. The starter is a built-in template driven by the project. Day Trader offers local routes only.
2. Tools and models can change the preferred route for a category in this workspace. Providers settings shows the same preference. T3's native picker selects the account instance, model and supported options. The choice belongs to this project. With one eligible option there is a shortcut to select it. A missing connection retains the choice for inspection. Affiliate research and initial Clipper footage requests also use the project preset. Clipper follow-up questions stay with the selection from the original footage request.
3. For an AI request, the creator can enter their own direction or bring suggested project details into the text box. **Review exact request** shows the instructions, allowed fields and selected text. The T3 action opens an unsent draft. On-device AI uses a local browser language-model session when its English text capability is already available. The runtime controls that model and exposes no effort picker. [Chrome language model documentation](https://developer.chrome.com/docs/ai/prompt-api)
4. After sending in T3, return to the same project and step and choose **Read completed reply**. The tab checks its saved request against the thread, run, selection and response. Incomplete or unrecognized results leave the project as it is. A tab reload retires pending reply associations.
5. Read the proposed replacements. Uncheck individual changes, apply the selected ones together, or dismiss the preview. Undo restores previous values when those fields still match the applied change. Revision checks prevent an old suggestion from overwriting later edits. Specialized sheets such as publication and evidence review provide guidance while the original controls retain authority.

Standard T3 chat keeps the permissions configured for that workspace.
