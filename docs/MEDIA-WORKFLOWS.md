# Choosing a look for a video or clip

The builder should let someone say “keep the screen readable and use captions like this,” see it on their own footage and change their mind before rendering a whole video. This is a design for the Video and Clipper projects. The existing Windows walkthrough covers the earlier style picker and tool checklist. [Windows walkthrough](acceptance/WP08.md) · [Planned Clipper builder](CLIPPER.md)

## Where the choice appears

| Starting project | A useful first journey |
| --- | --- |
| **Blank** | Collect a recording, a screenshot and a note about the intended audience. Pin a reference for later. When the user chooses a media workflow, offer the selected material and show precisely what will carry over. |
| **Digital product** | Select a reviewed exercise from a workbook and choose **Make a video from this**. Start a linked Video project with that exercise, its source revision and reuse terms. Preview one worked example as a short lesson. Updating a caption leaves the original workbook intact. |
| **Video** | In **Choose a style**, pick a sample, supply a reference, ask for suggestions or use the plain look. Then review the tool checklist, brief and storyboard. Use the creator's first scene for an inexpensive proof before approving the look across the sequence. |
| **Clipper** | Choose a recording and mark a moment first. In **Edit**, compare looks over that moment. For an interview, try a speaker crop with quiet captions. For a screen demo, keep the entire interface visible and add a callout. Apply the chosen settings to one variant, or explicitly select several. |

Video exposes detailed controls in its existing steps. **Style** opens trait controls from the sample picker. **Prepare** expands each action to show its version, host, route and data use. **Brief** pairs a plain-language goal with audience, duration and aspect targets. **Storyboard** pairs a scene outline with exact durations, sequence and caption cues. **Assets** pairs Library selection with track placement, attribution and permitted uses. **Render** pairs a sample preview with an immutable snapshot and a preset. **Review** pairs playback with frame, audio and caption inspection. **Export** pairs a local save with bundle contents and format settings. **Publish** pairs a single approval with account, visibility and receipt details. Each step preserves the current project when switching controls. Clipper uses the same convention from Source through Export and optional Publish. [Clipper stage controls](CLIPPER.md)

## What the builder saves

**Help me pick references** works for someone with an idea and nothing to upload. Start with original Studio examples and the project's permitted Library. Suggest up to three visibly different options with a preview and a short reason tied to the goal. For “show how I fixed checkout,” offer a full-screen demonstration and a narrated close-up so the user can judge legibility. If the user chooses broader research, show source, creator, usage terms and eligible preview for each result. An unverified URL can stay on the board as a note. The user can select one example, combine named traits from several or skip the board.

1. **Choose a starting point.** Offer original Studio samples with motion previews, a manual starting point and “Use my reference.” A reference may be a permitted local video interval, a still, a Library revision or a text description. Save a URL as a reference note until permitted media is available. The source used for clip content has its own role and permissions.
2. **Choose what to borrow.** Give each reference a small list of editable traits. One can guide pacing, another caption placement. Expose aspect ratio, crop/layout, approximate shot length, type size, caption position and motion intensity in plain language. Preserve manual edits and identify conflicting choices. A screenshot supports framing and color observations. It needs user input or moving footage to establish pacing. Using a palette or timing never inserts the reference's footage, voice, music, font files or logo.
3. **Compare on the same material.** Show the original cut and one or two candidate looks on the same few seconds. Include a still-frame equivalent for reduced motion and keyboard-accessible replay. “Help me choose” explains a visible tradeoff, for example, “the speaker crop hides the button the viewer needs to see.” Allow manual overrides, discard, or save a named look. A skip goes straight to the plain offline path.
4. **Review the stack as actions.** Show what is ready on this device, what would need preparation, what data leaves and what may cost money. A simple trim may need only the local renderer. A kinetic title may need a composition renderer. Save tool choices separately from the look. Selecting a preview grants no install, account access or upload. Approval names the exact tool and host for the requested action.
5. **Apply, reopen and revise.** Bind the accepted settings to the sample, source and variant revisions. Changing style creates a new revision. Preserve source intervals, transcript corrections and sibling variants, and mark affected render or publication approvals stale. Export the local video and its editable settings. For a new project, reuse a saved look with fresh bindings to that project's media, host and permissions.

## Recipes people can finish

| Goal | Assistance worth offering | What the creator reviews |
| --- | --- | --- |
| **One answer from an interview** | Optionally transcribe on device, suggest question/answer intervals with transcript spans, and offer a speaker-focused or full-frame layout. | Play the lead-in and the end of the answer, fix names and caption breaks, then save the portrait clip. |
| **A feature demo that works on mute** | Mark the successful action by hand or suggest a moment from observed frames. Keep the interface legible. Offer restrained callouts and a human-written caption. | Watch the same action full-frame and cropped. Check that the control, result and text are visible on a small screen. |
| **A streamer’s highlight** | Start with an owned recording, a manual marker or a suggested moment. Show a game-and-camera split when useful. Offer an optional post-stream import through a qualified OBS connection. | Move or hide the camera crop and adjust the cut. Queue several candidate clips for private review. Each selected export has its own revision and status. |
| **A narrated explainer or workbook teaser** | Pull the approved source excerpt, suggest three scenes, set a look and compare a title card made from the user's content. Offer recorded narration or captions, with paid voice generation priced separately. | Approve the first scene and its timing before applying the treatment to the sequence. Hand the finished local video to Clipper to make shorter versions if desired. |

## Tools and activation decisions

| Task | Candidate and integration decision |
| --- | --- |
| **Find and prepare highlights** | **Studio** owns the import, moment selection, edit document, render and review by default. **SupoClip** is a design reference for guided generation and editable drafts. **Clips Kitty**, formerly **Clips Studio**, is an optional bring-your-own integration for an explicitly selected highlight action. Its MCP requires an already running engine. See the route and licensing conditions below. [Clips Kitty rename](https://github.com/ColinGPT9/clips-studio/releases/tag/v1.1.3) |
| **Hand off a finished stream** | Clips Kitty's separate **OBS dock** provides a concrete example. A planned Studio handoff would use the creator's chosen source and open a proposed import. There is no need to connect OBS to clip a local file. [OBS integration](https://github.com/ColinGPT9/clips-kitty-obs-plugin) |
| **Animate a title, explainer or overlay** | **HyperFrames** uses HTML compositions and publishes agent guidance for editing, rendering and sampling styles. **Remotion** uses React compositions and also maintains agent skills. Show either as a candidate for an appropriate recipe. Qualify assets, fonts, browser isolation, network behavior, reproducibility and the exact build before enabling it. Model-generated composition code requires the isolated execution gate. Remotion distinguishes template-based services from accepting arbitrary Remotion projects for server rendering. Keep the hosted use case gated on terms that cover the intended service. [HyperFrames skills](https://github.com/heygen-com/hyperframes/blob/main/docs/guides/skills.mdx) · [Remotion agent tools](https://www.remotion.dev/docs/ai) · [Remotion license FAQ](https://www.remotion.dev/docs/license/faq) |
| **Read, transcribe, trim and deliver media** | **ffprobe** inspects local tracks. **FFmpeg** is the first local trim/crop/encode candidate. **whisper.cpp** can supply an optional draft transcript, and **PySceneDetect** can supply visual cut points. Show each only when a recipe calls for it. Manual marks and typed captions remain available on a silent recording. [Technical choices and qualification](CLIPPER.md) |
| **Import an authorized online recording** | **yt-dlp** is an optional acquisition candidate for supported, permitted downloads. A creator can also use the platform's own export and import the local file. An approved network import is scoped to the chosen URL, destination and size limit. Credentials from the user's browser, arbitrary downloader arguments and executable hooks are outside the proposed adapter. If the service requires verification, restricts download or rate-limits the request, retain the note and offer local import. [yt-dlp project documentation](https://github.com/yt-dlp/yt-dlp) |
| **Continue in another editor** | **OpenTimelineIO** is a candidate for a future editorial handoff. It describes cuts, tracks and external media references. Any supported editor and adapter must round-trip a fixture with matching time ranges and disclose which effects and captions carry across. The standalone video remains the primary deliverable. [OpenTimelineIO documentation](https://opentimelineio.readthedocs.io/en/latest/) |
