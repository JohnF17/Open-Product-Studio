# Implementation decisions for the first desktop build and its dependent milestones

18 November 2026. Acceptance owners, target files and per-criterion evidence live in the [work-package contracts](../WORK-PACKAGES.md). The following decisions define what those owners must demonstrate as each capability enters a release.

## Packaging and import (WP01–02)

Import the complete ancestry of the pinned T3 revision. Record its commit, tree, parent and lock digest. Preserve a path-and-hash manifest of the original public Studio files and resolve the README, AGENTS, CONTRIBUTING, LICENSE, ignore rules and PR template individually. Keep upstream notices and scope original Studio materials under their existing license. Review inherited release, relay and CI workflows before enabling them for the fork.

Use a clean Windows user or isolated build environment with synthetic state, seeding disabled, a dedicated data path and a sanitized environment. Review the worktree setup, prepare and native build hooks before running them. The WP01 receipt records installed Node/pnpm versions, frozen build command, both staged production dependency graphs and native module provenance. Maintain a reviewed public path list through checkout, staging, packaging and extraction. Keep private research and local environment files outside build inputs.

WP02 binds the Windows installer hash to its executable identity, AppUserModelID, protocol, vault and data paths, updater/feed configuration and packaged server. Run the installed build beside a synthetic T3 profile with upstream connectivity blocked. Demonstrate an empty account-free start, authenticated loopback backend, native module and PTY loading, Unicode paths, persistence across a second launch, and uninstall. Qualify each advertised architecture/runtime separately. Signed distribution and populated Studio upgrade evidence belong to E1/E7 and WP07.

## Local agent operations (WP04–06, WP09, WP12, WP52–57)

The worker persists the operation ID, command digest, approval, reservation, replay policy, attempt generation and reconciliation method **before** starting an effect. Each re-entry, including a generic worker failure retry, reads the authoritative operation record. Reads and local pure transformations may retry within budget. A provider operation may retry under the *same* supported idempotency key only while its documented scope and validity hold. After an ambiguous non-idempotent dispatch, keep the resource fenced, reconcile through the original account, and preserve Unknown when the provider cannot establish the outcome. A user's request to try again must disclose the uncertainty, cost and duplicate risk and receive a new scoped decision.

Use the existing transaction/outbox bridge. Distinguish provider acceptance, uploaded bytes, adoption of an immutable revision, usage settlement and downstream intent. Restart twice after each failure point, verify one logical settlement and artifact adoption, and preserve manually edited/newer revisions. Delivering a child run twice uses the same logical result ID.

Driver qualification starts on Windows. For every proposed CLI, record the complete launch chain, binary/driver versions, effective account, supported options, identity reporting, OS restrictions, Studio and native tool paths, child ceilings, trust and any limitations. Advertise guided CLI work for a build after at least one real Windows CLI passes its promised actions. Retain the chosen account/model/effort during an outage, reroute or version change. Offer a broker-only lane when native tools can be disabled and a supervised lane when every relevant operation stops for enforceable approval. Present manual work and explicit alternative connections for unavailable actions.

Bundle signed/versioned local qualification fixtures, expected checks and account-call disclosures. A changed binary invalidates its affected evidence. Show which local checks passed and what further evidence is needed. Fixture-only inspection can re-enable a lane whose complete contract can be proven locally. Any required external probe has a disclosed quota/cost and a separate authorization. Ordinary opening, editing and installed export work offline.

## Shared digests (WP04, WP07, WP17, WP34–35, WP55)

For each purpose define a validated envelope containing purpose, schema version, scope and typed payload. Serialize it using UTF-8 RFC 8785 JSON canonicalization, then SHA-256. Reject duplicate object keys, unknown schema versions, unsupported number representations and unpaired Unicode surrogates before hashing. Define defaults, omission/null, ordered plans and set-valued fields in the schema. Sort set-valued fields by stable identity after uniqueness checks. Preserve exact model options, revision, recipient, price/currency and asset-byte hash. Use tested integer minor units or schema-defined decimal strings for money. Hash raw asset bytes separately and use original provider-signed bytes for webhook verification. [JSON Canonicalization Scheme](https://www.rfc-editor.org/rfc/rfc8785)

Golden vectors run in desktop, importer and cloud. They include reordered keys, omitted versus explicit defaults, composed/decomposed Unicode, ordered action lists, empty strings, stale authority scope, changed currency and changed blob bytes. A duplicate command with the same digest returns the original receipt. Different meaningful input under a reused key raises a conflict.

## Hosted editing, execution and access (WP33–37)

WP33 owns Convex repositories for project, evidence, content, relationships, engagement, distribution, insights and execution records admitted to cloud ownership. Each accepted context has an explicit command/read schema, capability and migration range. WP34 checks the per-context support matrix and asset manifest before switching ownership. It blocks handover when an active operation lacks custody or when preserving/editing a required context is unsupported. The owner may instead export a labeled portable snapshot. The new writer commits domain changes, event, command receipt and effect intent atomically through Convex. Every command checks current membership, parent/object ownership, epoch, expected revision, admission policy and idempotency digest. UI reads come from a checked projection of that authority.

| Durable record | Single writer and key | Recovery after worker loss |
| --- | --- | --- |
| Project revisions, events and commands | Convex command mutation keyed by workspace/project, ownership epoch and command ID | Read current revision and receipt. Reject an obsolete local writer. |
| Plan, node, attempt and native checkpoint | Convex job journal keyed by logical run/node and attempt, written under current lease generation | Load immutable selection and last committed checkpoint. Reconstruct the retained harness and adapter state or fence a non-resumable run. |
| Admission, reservations and dispatch intent | Convex transaction keyed by operation, payer, grant and lease generation | Inspect recorded intent and replay policy before contacting the provider. Revalidate payer/membership/host immediately before dispatch. |
| Provider receipt and late completion | Account-scoped receipt inbox keyed by provider/account/mode, native external ID and operation | A current reconciler adopts late facts using the original binding. A superseded worker cannot finalize them. |
| Uploaded artifacts and accepted result | Verified immutable bytes plus a revision/manifest/receipt transaction under the current epoch | Reuse verified staged bytes or collect expired orphans. Adopt once and record stale input or missing bytes explicitly. |
| Cost settlement and subsequent intent | Billing and execution transaction with unique usage/operation keys | Reconcile observed provider usage against the original reservation. Preserve unknowns and outstanding holds until resolved. |

WP36 hosts the same harness, command contracts, T3 execution semantics and reviewed commercial provider adapter on an isolated worker. Use WP12's official-protocol conformance contract with independently held commercial credentials and route-specific qualification. Convex stores reconstructible state for every acknowledged transition. Worker-local SQLite/filesystem is a cache/spool and can disappear between transitions. Native operations whose state cannot be recovered or reconciled stay disabled for that hosted route. Test by removing *all* worker-local state after admission, after fake provider acceptance and after upload. Race leases, revoke membership, change payer, reconcile late receipts and hand back to local. Verify exactly one authorized revision and settlement or an explicit Unknown hold.

The hosted web client uses Clerk's supported Convex integration. The packaged desktop candidate uses a dedicated public OIDC client, the external system browser, S256 PKCE, state and nonce, and a once-only loopback callback. Convex verifies the ID token for the expected issuer, audience and signature keys before internal-user and workspace authorization. Record discovery/JWKS configuration and provider subject mapping, and validate ID-token claims including nonce at the client. The desktop main process stores refresh material in the OS vault, brokers scoped requests and revokes/clears the session on logout. A packaged test measures expiry, revocation latency and membership withdrawal, including a pending A action while B is open. If the provider/configuration cannot supply a suitable ID token and refresh path, keep packaged hosted access disabled pending a reviewed alternative. Public web and local desktop can qualify independently. [Clerk native sign-in](https://clerk.com/blog/adding-clerk-auth-to-your-cli) · [Convex OIDC](https://docs.convex.dev/auth/advanced/custom-auth) · [Convex and Clerk](https://docs.convex.dev/auth/clerk)

E4 must settle unused purchased-unit consumption, voluntary refund terms, mandatory rights, original-tender failures, support, retention and reserve coverage in the actual operating jurisdiction. Model shutdown with no new sales. Test concurrent spend/refund, failed refund, disputed prior spend, delayed settlement, payer closure, buyer delivery and project export. Record policy and actual service costs before committing to rates for the proposed $19.95 experiment.

## Personal mail and pairing (WP09, WP25, WP38, WP62)

WP09 supplies the account-scoped mailbox ingress contract (cursor, backfill, authenticated event, dedupe, limits and revocation). WP25 adds campaign contacts, suppression and sender readiness. WP62 implements private AgentMail correspondence directly against the common contract. Exercise a gap/backfill, duplicate event, unsent local draft and independent provider shutdown with CRM, campaign, browser and phone disabled. Each external draft, send, or standing action keeps its own grant and channel activation.

The first paired control profile supports a directly reachable host on a user-managed LAN or VPN. TLS terminates at the selected host with a verified certificate or an out-of-band verified host fingerprint on a supported client. Bind a one-use pairing challenge to the peer and a revocable device grant with project/action scope. A browser client must be able to validate the host's HTTPS identity. Test sleeping hosts, incompatible versions, lost devices, late callbacks and denied cross-project access. Record the actual transport and supported clients in build evidence. Expand reachability through a relay only after protocol, privacy, operating-cost and failover review.

## Launch evidence

Each release claim points to a build, platform, supported provider/action and a completed witness. For an initial M2 guided result record cohort, assistance rubric, hardware and eligibility before the pilot. Exercise idea to recommendation or evidence-based abstention, human edit, reviewed sample/export and external-reader reopen with M3 and cloud disabled. Use the roadmap's four-of-five novice gate. Report setup, model, edit, export and reopen times individually, and count interventions and abandonment. The same release record links keyboard, reduced-motion, screen-reader and interrupted-quota cases.

Direct launch uses an eligible creator-owned merchant and version-bound asset. A replayed order, later refund and a closed Studio desktop exercise the buyer's support and delivery path. Service work demonstrates permitted inputs, revision allowance, approved sample and unsent pitch. Users can enter manual observations and revise a draft with messaging disabled. Cross-project witnesses use identical display names, a pending run and approval, a revoked seat and a delayed callback. Inspect which project owns each result and cost.

Later releases record independent tests for licensed lead data, media cost, course access, client invoices and e-signature, live collaboration, private Dot event replay and external automation only for the selected capabilities. Owners record the source of external authority, scope, cost and support path for each enabled action.
