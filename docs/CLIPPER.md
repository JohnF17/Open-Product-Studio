# Clipper projects

Clipper starts with a video and an instruction. A teacher might drop in a lesson and ask for three self-contained explanations under 30 seconds. A developer might record a window and ask for the two moments that show a feature working. The guided path finds candidate moments in the source, explains each pick and lets the creator preview, adjust and export several clips together. Manual marks remain available on the same timeline.

Social video pages are saved as references. A browser with a screen-sharing chooser can record a silent surface. The desktop build accepts an exported recording file.

The original recording stays on the device. Check the selected account, model and effort and send when ready. Advanced settings explain aspect, resolution, captions and placement and can open a separate AI question.

## The first clip

In **Moment**, choose a local recording you have permission to use. Scrub to each endpoint, choose **Set mark in** and **Set mark out**, then **Preview selection**. You can also enter both times by hand. The project saves your marks. Its active session retains the selected video as you move between sheets. After closing and reopening the project, reattach the recording and confirm the saved marks against it.

In **Edit notes**, type a caption and try Subtitles, Headline or Callout on a sample frame or a permitted still. In **Export**, choose **Trimmed clip** for a caption that begins at zero or **Original recording** to preserve the source timecodes. The WebVTT file contains one plain-text cue. Styling instructions, source notes and framing choices stay in the separate JSON edit plan. The desktop and phone-width walkthrough exercises local recording playback and both caption timelines. [Clipper acceptance record](acceptance/WP24/clipper-marks/README.md)

The table below describes the full workflow. You can already render and download reviewed cuts in Chromium. Restoring recordings across sessions, cutting on exact frame boundaries and publishing to a social account each have their own acceptance test.

## Tool decisions

| Tool | Decision and evidence |
| --- | --- |
| **FFmpeg and ffprobe** | First candidates for a Windows local renderer and media inspection. Probe the selected local file and qualify an exact encoder build, configuration and export preset before distribution. Seeking between keyframes needs a decoded-frame acceptance test. Build options and linked libraries affect redistribution obligations. [FFmpeg manual](https://ffmpeg.org/ffmpeg.html) · [ffprobe manual](https://ffmpeg.org/ffprobe.html) · [Build licensing](https://ffmpeg.org/legal.html) |
| **whisper.cpp** | Candidate for optional on-device speech transcription. Show the model, download size and disk requirement before preparation. Keep machine timings editable and save corrections as revisions. Test speech, silence and background noise before enabling the action. [Project documentation](https://github.com/ggml-org/whisper.cpp) |
| **PySceneDetect** | Candidate for optional visual navigation. Its shot-change detector returns time ranges. A user can inspect a transition or use those frames to ground a suggestion. A static screen recording can still contain an excellent manual clip. [Detection and export documentation](https://www.scenedetect.com/docs/latest/) |
| **OpusClip and OpenClipper** | Product references for prompt-based moment selection, caption editing and reframing. OpenClipper also describes a local desktop workflow and batch export. Use these as comparisons when testing how quickly someone can find, correct and export one good clip. [OpusClip tutorials](https://www.opus.pro/learning-center) · [OpenClipper repository](https://github.com/GrepCut/OpenClipper) |
| **Vizard** | Candidate only if users later need hosted processing. Its API uses paid upload minutes and returns a project ID before results are available. Show the files leaving the device, account and bounded charge before upload. Reconcile that ID on interruption. Adoption requires a separate provider decision and live qualification. [Billing](https://docs.vizard.ai/docs/pricing) · [Job response](https://docs.vizard.ai/docs/response) |

The basic tool checklist contains a local media reader and renderer. Transcription, scene detection and model-assisted selection appear only for the actions that use them. A creator can inspect what each action reads, where it runs, whether anything leaves the device and what it costs. No additional hosted service is required for the first export.

## Project, edit and provider boundaries

- Studio owns one Clipper project and one edit model. A moment refers to an immutable Library source revision. Each variant has its own versioned edit document with the chosen source ranges, crop, captions, audio settings and optional layers. The guided controls, timeline, preview, renderer and reopened draft read that document. Assistance results attach to this project as proposals. Any external job stays outside the Studio edit history until an accepted proposal creates a revision.
- Use the built-in editor and one qualified Studio renderer for the first local export. If a qualified external action is chosen, bind exactly one execution route and host for that action. Studio does not auto-start a vendor engine, mirror jobs to another backend or run competing routes for the same request. External job and clip IDs are provenance. Import only validated source-aligned proposals or explicitly selected output files with rights. A rendered file without a verifiable source map can be imported as a new media revision through the Library. [Integration decisions](MEDIA-WORKFLOWS.md)
- Keep manual and assisted edits in one undo history. For example, **Use this moment** previews the suggested range and **Propose an edit** can shorten a pause or restyle captions. Show a before/after preview and a list of changes, including any unsupported request. Accept the chosen changes as one transaction, or dismiss them with zero writes. Undo and redo restore edit settings and timing as a unit. Autosave the applied revision, current step and recoverable history on the owning device.

## Editing and agent contracts

- Save each cut as a half-open interval `[in, out)` in the source presentation timeline. Store integer timestamps with their rational time base, chosen tracks and source revision. For split or reordered edits, derive an output timeline from the ordered source ranges and map proxies, audio and caption cues through those ranges. Use decoded presentation times for variable frame rate footage and audio offsets. Preserve rotation and pixel aspect ratio when translating a crop from preview to output.
- An agent proposes an interval, a brief reason and the evidence a person can open. A quoted line requires a span in the identified transcript revision. A visual suggestion requires observed frames at source times. Reject nonexistent revisions, out-of-range marks and unsupported quotes. Allow an empty result. The user can tighten both handles before saving.
- Run Studio model suggestions through the existing T3-backed harness. Bind host, provider, account, model and supported settings for each transcription, moment analysis or edit action that uses a model. Show readiness, exact inputs (audio, transcript excerpts or frames as applicable), what leaves the device, retention and charge limits before consent. A locally running CLI can call a hosted model. A missing model, unsupported modality or provider error leaves manual editing available. Any different route needs its own selection and approval. Source metadata, filenames and transcript text enter as data. A proposal cannot approve an upload, spend, render or post. [Harness contracts](AGENT-HARNESS.md)
- Suggestions carry project, source, edit-base and evidence revision IDs, with stable target IDs and an allowlisted operation schema. Start with setting In/Out, correcting a named caption cue and changing an exposed caption setting. Validate source bounds, cue references, rights and supported operations before showing the proposal. Check rights and compare revisions again at Apply. After a trim, caption edit, undo, source relink or concurrent save, a result for a superseded base is stale. Keep it visible as stale and offer recompute from the current draft or discard. Save conflicts preserve the unsaved copy for comparison or recovery and offer reload or save as a new variant. Reopen checks the saved base and any pending job by ID before enabling Apply.
- Carry permissions from source to derivatives. Check the intended audience and destination again before export or publication. Bind each render to source, edit, preset and renderer revisions. Write to a temporary destination, validate the output, and promote it atomically. Cancellation or low disk space leaves the last good export intact. Retention applies to proxies, transcripts and temporary renders as well as library assets.
- Bind publishing approval to the rendered bytes, destination account and post settings. Changing a cut invalidates approval for that variant. A timeout after submission preserves the original operation for reconciliation. A project change, app restart or batch retry must never retarget or duplicate a post. [Publication and service boundaries](PLATFORM-BOUNDARIES.md)

## Job failures and recovery

Show the current stage, last confirmed update and next action on the existing Studio job card. Track acquisition, probe, transcription, analysis, proposal validation and render separately. Check worker health, queue pickup and source availability separately. A disconnected progress stream is an unknown state until status is reconciled. Preserve the durable operation ID, selected route and validated intermediate outputs across restart. Do not infer progress from a successful status fetch. [SupoClip troubleshooting reference](https://github.com/FujiwaraChoki/supoclip/blob/0633c307ffcd7b4854389473cc9802c6d13c5815/docs/troubleshooting.md)

| Outcome | Recovery in Studio |
| --- | --- |
| Source missing, restricted, download failed, or unsupported media | Keep marks and the source reference. Explain the stage error and offer a matching authorized local file or an explicitly selected eligible import. Never substitute footage or use a baked export as the original source. |
| Worker unavailable, queue paused or returning an existing job | Stop at a clear status. Offer to reconnect or reconcile the original ID. Distinguish a duplicate with existing results, an unknown ID and a completed analysis with zero valid suggestions. **Mark by hand** stays available. |
| Transcription/model failed, timed out, or returned unusable results | Keep successful stages and edits. Offer retry of the failed stage on its same qualified route after resolving the prior attempt and confirming any new charge. Offer manual marks or captions immediately. A request for a different route goes through its own consent. |
| Preview or render failed, cancelled, or completed after newer edits | Keep the edit and last good export. Record the failure cause, including disk, encoder, font or missing-asset errors, and retry the immutable snapshot or review a newer revision first. Label a successful older render with its revision and keep it out of current approval. |
